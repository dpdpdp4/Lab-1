# Матриця доступу — ЛР4, baseline 2-A

## Загальні правила

- Неавторизований користувач не має доступу до захищених операцій (HTTP 401).
- Reporter працює лише з власними інцидентами.
- Analyst має права читання для аналізу та може виконати лише дозволений перехід статусу.
- Administrator не отримує автоматичного доступу до інцидентів.
- Для чужого або відсутнього інциденту повертається HTTP 404.
- Власник і роль визначаються сервером з автентифікованого користувача, а не з даних запиту.

## Матриця доступу

| Дія | Reporter | Analyst | Administrator | Власник ресурсу має значення? | Стан реалізації |
|---|---|---|---|---|---|
| Перегляд списку | Лише власні | Усі інциденти | Ні | Так для Reporter | Реалізовано |
| Перегляд деталей | Лише власні | Усі інциденти | Ні | Так для Reporter | Реалізовано |
| Створення інциденту | Так | Ні | Ні | Власника призначає сервер | Реалізовано |
| Редагування Title/Description | Лише власні | Ні | Ні | Так | Реалізовано |
| Видалення інциденту | Лише власні | Ні | Ні | Так | Реалізовано |
| Зміна severity | Ні | Ні | Ні | Ні | Реалізовано |
| Зміна status | Ні | Лише New → Triaged | Ні | Ні | Реалізовано |
| Перегляд звичайного коментаря | Лише у власному інциденті | Усі інциденти | Ні | Так для Reporter | Реалізовано |
| Перегляд internal comment | Ні | Так | Ні | Ні, але доступ до батьківського інциденту перевіряється | Реалізовано |

## Політика IDOR/BOLA

Ідентифікатор інциденту сам по собі не надає права доступу до ресурсу. Для Reporter сервер перевіряє `OwnerUserId`. Analyst може читати інциденти незалежно від власника, але не отримує права редагування чи видалення.

Під час доступу до дочірнього ресурсу, зокрема коментаря, сервер також перевіряє права на батьківський інцидент.

Зміна власника, ролі користувача, severity або status не повинна дозволятися через довільні поля запиту. Перехід `New → Triaged` виконується окремою захищеною операцією.
